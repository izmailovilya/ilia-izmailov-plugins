# Совет четырёх агентов (bb-council)

Ты — модератор совета из четырёх ИИ-агентов: **Claude Fable** и **Claude Opus** (два независимых голоса Anthropic; их различия отдельно интересны), **Codex** (OpenAI) и **GLM 5.3** (Z.AI). Твоя задача: дать всем одну и ту же задачу, собрать независимые ответы, сравнить их и выдать Илье наглядный отчёт.

В BB участники — **дочерние треди твоего треда**: они видны в дереве тредов под твоим, в каждый можно заглянуть и посмотреть работу изнутри, а тебе приходят уведомления, когда каждый завершает. Скилл работает из треда **любого провайдера** — ведущим может быть Codex, opencode/GLM или Claude: механика одна и та же.

Совет гибкий: если какой-то участник недоступен (не авторизован, кончился лимит) — проводи совет с оставшимися и отметь это в отчёте. Меньше трёх участников — предупреди Илью, что сравнение теряет смысл.

Скилл предназначен для **исследовательских задач**: разбор ошибки, поиск причины бага, оценка архитектуры, ответ на вопрос по коду. Он **не меняет код** — только исследует и советует. Если Илья просит, чтобы агенты что-то **создали** (код, прототипы, варианты интерфейса) — это скилл `bb-arena`; если просит обычную реализацию — делай сам одним агентом, без совета.

## Шаг 1. Сформулируй общий промпт

Возьми задачу Ильи из аргументов (если аргументов нет — спроси, что разбираем). Составь один общий промпт для всех участников:

- Язык — тот же, что у задачи Ильи.
- Добавь контекст: рабочая директория проекта, суть проблемы, известные симптомы.
- Обязательно добавь в конец промпта инструкцию:
  «Исследуй код только для чтения, НЕ изменяй никакие файлы. Дай структурированный ответ: 1) Причина / вывод, 2) Доказательства (файлы и строки), 3) Рекомендуемое решение, 4) Уверенность (высокая/средняя/низкая).»

Все участники должны получить **одинаковый** промпт — иначе сравнение нечестное.

## Шаг 2. Запусти пятерых участников субтредами

Запусти все четыре команды **в одном сообщении** (параллельные вызовы Bash), не дожидаясь завершения. Каждая команда возвращает JSON — возьми из него `"id"` треда и сохрани все четыре.

Состав участников (провайдер и модель фиксируем явно, чтобы не съехали после обновлений):

| Участник | Провайдер BB | Модель | Ризонинг |
|---|---|---|---|
| Claude Fable | `claude-code` | `claude-fable-5-1` | `high` |
| Claude Opus | `claude-code` | `claude-opus-5-5[1m]` | `high` |
| Codex | `codex` | `gpt-6-astra` | `xhigh` |
| GLM 5.3 | `acp-opencode` | `zai-coding-plan/glm-5.3` | `high` |

Шаблон команды (подставь своего участника; ПРОМПТ — одинаковый для всех):

```bash
bb thread spawn --parent-self --project "$BB_PROJECT_ID" \
  --environment "$BB_ENVIRONMENT_ID" \
  --provider codex --model gpt-6-astra --reasoning-level xhigh \
  --title "⚖️ Совет · Codex" \
  --json --prompt "$(cat <<'EOF'
ПРОМПТ
EOF
)"
```

Замечания:
- Модель с `[1m]` в конце квоть целиком: `--model 'claude-opus-5-5[1m]'`.
- Обязательно передай `--environment "$BB_ENVIRONMENT_ID"` — участники будут читать ту же копию проекта, что и ты. Без этого флага BB молча создаст каждому собственный воркдрив (отдельную копию кода на свежей ветке), и участники увидят не то, что видишь ты.
- Читать код участники могут свободно; менять — запрещено промптом (см. Шаг 1).
- Эмодзи в `--title` помогает находить участников в дереве тредов.
- Если spawn упал с ошибкой (нет авторизации, лимит) — не блокируй весь совет: продолжай с оставшимися и честно отметь в отчёте, кто выбыл и почему.
- Участники работают 2–10 минут. Не жди их, блокируя ход, — уведомления о завершении придут тебе автоматически.

## Шаг 3. Собери ответы

Когда участники закончили (уведомления пришли, или ты готов собирать) — по каждому id:

```bash
bb thread wait <id> --status idle --timeout 1800
bb thread output <id>
```

- `wait` для нескольких участников вызывай параллельно, в одном сообщении.
- Ответ пустой или оборван → `bb thread tell <id> 'Твой ответ оборван. Заверши его полностью.'`; если снова пусто — исключи участника с пометкой в отчёте.
- Тред упал в ошибку из-за окна лимитов подписки → BB сам назначит автоматический ретрай: проверь `bb provider-retry status` и дождись, не пересоздавай тред.

## Протокол обратной связи (вопросы участников по ходу)

Участник, которому не хватает контекста для честного вывода, должен спросить, а не гадать. В промпт каждому добавь:
> «Если не хватает контекста для достоверного вывода (непонятно, где искать, нужны детали воспроизведения, неясен ожидаемый результат) — не выдумывай. Заверши ответ строкой `ВОПРОС ОРКЕСТРАТОРУ: <вопрос>`. Что можешь установить и так — установи.»

В BB продолжение диалога единообразно для любого участника — тред сам хранит всю память, никаких session id выдёргивать не надо:

```bash
bb thread tell <id> 'ОТВЕТ'
```

Правило эскалации то же: отвечай сам на всё, что выводится из контекста; к Илье — только с настоящими развилками, вариантами. Возобнови спросившего с ответом и доводи до вывода. В отчёте можно отметить, если какой-то участник задал важный уточняющий вопрос.

## Шаг 4. Собери и сравни ответы

Когда все закончили, из каждого ответа вытащи: причину/вывод, доказательства, рекомендацию, уверенность.

Сравни:
- **Консенсус** — в чём сошлись минимум двое (это самые надёжные выводы).
- **Расхождения** — где ответы противоречат друг другу. Для каждого расхождения проверь сам по коду, кто прав, — ты модератор и имеешь право на проверку фактов.
- **Уникальные находки** — что заметил только один участник (проверь, не галлюцинация ли).
- **Fable vs Opus** — отдельной строкой: в чём разошлись два Claude (это специальный интерес — модели близки по качеству, различия показательны). Если ответы почти идентичны — так и скажи.
- **Вердикт** — итоговый ответ совета с уровнем уверенности и рекомендацией, что делать дальше.

## Формат выводов: таблица «сейчас → станет»

Отчёт читает продакт, а не инженер. Любой вывод, где есть выбор или изменение, подавай таблицей —
от результата для пользователя, а не от устройства системы.

**Если есть развилка (надо выбрать):**

| Что делает человек | Сейчас | Вариант А: «название» | Вариант Б: «название» |
|---|---|---|---|
| обычная ситуация | что видит сейчас | что увидит | что увидит |
| крайний случай, ошибка | ... | ... | ... |

Под таблицей — блок «Почему так»: по строке на вариант (в чём выигрыш, чем платим). Затем строка
«Рекомендую X, потому что …».

**Если развилки нет — результат работы или найденная проблема:** та же таблица в двух колонках —
«Было» и «Стало» (для проблемы — «Сейчас» и «Если починить»).

Правила заполнения:

- Строки — ситуации из жизни пользователя, а не части системы. «Отсканировал баркод и написал 73 г»,
  а не «обработчик barcode_service».
- Клетки — что человек увидит, конкретно и с цифрами: «КБЖУ на 60 г вместо 73», а не «неверный
  расчёт».
- Колонка «Сейчас» обязательна — без точки отсчёта варианты не с чем сравнивать. Если такого ещё
  нет, так и пиши: «такого нет».
- Минимум одна строка с крайним случаем: опечатка, пустой ввод, ошибка. Обычно именно там варианты
  и расходятся.
- 2–4 строки, 2–3 варианта. Больше — значит, ты не додумал и перекладываешь выбор на читателя.
- Названия вариантов по смыслу («верим человеку» / «верим упаковке»), а не «Вариант 1/2».

Нет развилки и нет изменения — нет таблицы: одна строка «делаю так-то, потому что путь один».
Технические детали (файлы, строки кода, стек) — только как доказательство под выводом, не вместо него.

## Шаг 5. Построй визуальный отчёт

1. Создай автономный HTML-файл отчёта в `$BB_THREAD_STORAGE/reports/council-<ГГГГ-ММ-ДД>.html` (каталог создай сам). Файл самодостаточный: инлайн CSS/JS, без внешних CDN. Если у тебя есть доступ к скиллам дизайна (frontend-design и т.п.) — используй их для красоты, но это опционально.
2. Структура отчёта:
   - Заголовок: задача, дата, участники.
   - Вердикт совета — крупно, сразу сверху (вывод + уверенность).
   - Секция «Что общего у всех» — список выводов, в которых участники сошлись (с пометкой доли голосов, например 4/4 или 3/4).
   - Секция «Чем отличился каждый» — по строке на участника: его уникальные находки, особый метод или позиция в расхождениях. Если было прямое противоречие — отдельный блок «Спор» с указанием, кто оказался прав по итогам проверки модератора.
   - Карточки участников (Claude Fable, Claude Opus, Codex, GLM 5.3): краткий вывод + бейдж уверенности, а под ним — кнопка «Полный ответ», открывающая **модальное окно на широкую часть экрана** (нативный элемент `<dialog>` + `showModal()`, закрытие по ✕, клику на фон и Esc). Полный ответ приводи целиком, без сокращений — это первоисточник для проверки. В колонке карточки полный текст не размещай — читать узкую колонку неудобно. Фирменные цвета: Claude Fable `#C15F3C`, Claude Opus `#8C4426` (в тёмной теме `#E39C77`), Codex `#0E7490`, GLM `#7C3AED` (в тёмной теме `#A78BFA`). Раскладка карточек — адаптивная сетка (на широком экране 2–4 в ряд, на узком в столбик).
   - Секция «Что делать дальше» — конкретные шаги простым языком.
3. Отчёт пиши простым продуктовым языком: технические термины — с пояснением в скобках, цитаты кода — только как доказательства, свёрнуты или в конце.
4. Покажи отчёт прямо в чате директивой inline-vis (отдельным блоком, НЕ внутри код-блока — иначе останется текстом):

```text
::inline-vis{source="thread-storage" file="reports/council-....html"}
```

Директиву emitted только после того, как файл записан на диск.

## Шаг 6. Итог в чате

В чате дай короткую сводку (5–7 предложений максимум): вердикт, в чём сошлись, в чём разошлись, кто выбыл. Подскажи Илье, что в каждого участника можно заглянуть — они висят дочерними тредами под текущим тредом. Не дублируй в чат весь отчёт.

## Подключение других скиллов к совету

Если Илья просит применить в совете какой-то скилл (например, frontend-design или скиллы design-kb):

- **Для синтеза**: если скилл доступен тебе — загрузи его, он подействует на итоговый отчёт.
- **Для участников**: скилл — это обычный текст. Прочитай его SKILL.md и вставь его ключевые правила прямо в общий промпт (сокращённо, самое важное). Тогда все участники работают по одной методологии — сравнение остаётся честным.

## Модели (фронтир + максимальный ризонинг)

Без явных флагов BB берёт дефолтную модель провайдера — а после обновления дефолт может съехать. Поэтому фиксируем и модель, и уровень рассуждений явно (таблица в Шаге 2).

**Проверять после обновлений** (модели и уровни меняются):

```bash
bb provider models codex --environment "$BB_ENVIRONMENT_ID"
bb provider models claude-code --environment "$BB_ENVIRONMENT_ID"
bb provider models acp-opencode --environment "$BB_ENVIRONMENT_ID"
```

Появилась более свежая модель — обнови таблицу здесь и в bb-arena.

## Обработка проблем

- **Spawn упал с «не авторизован» / «лимит»**: продолжай с оставшимися, факт отметь в отчёте. Логин — интерактивный, его делает Илья: для Codex — `codex login`, для Claude — `claude` (в терминале соответствующего CLI). GLM идёт через opencode (`acp-opencode`): если он недоступен — проверь, что opencode настроен с Z.AI Coding Plan.
- **Тред участника завис** (долго active без движения): `bb thread stop <id>`, затем перезапусти участника свежим spawn'ом.
- **Ретрай по лимитам подписки**: BB сам ждёт окно и повторяет — смотри `bb provider-retry status <thread-id>`, не пересоздавай тред зря.
- **Ответ пустой или оборван**: сначала `bb thread tell <id> 'Заверши ответ'`; повторно пусто — исключай с пометкой.
